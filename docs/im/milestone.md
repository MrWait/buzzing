# IM 业务功能里程碑规划

## 概述

当前 IM 模块已完成基础 P2P/群聊、消息收发、Feed 列表、已读回执、Reaction、收藏等核心功能，可作为功能验证。本文档规划从当前基线到完整企业级 IM 的渐进式实现路径。

### Milestone 4: 搜索与发现 (2-3 周)

**目标**: 建立全局搜索能力，让用户可以快速找到消息、联系人、文件和群。

**技术选型**: PostgreSQL + pg_trgm 扩展，不引入独立搜索引擎（减少运维复杂度）。
- `summary` 列 + `pg_trgm` GIN 索引 → 模糊匹配、纠错
- `at_user_ids` 数组 → @提及搜索（已有 GiST 索引）
- `type`/`from_id`/`chat_id`/`created_at` → SQL 联合过滤
- 搜索范围限定在 `summary`（富文本正文等长内容不在 M4 覆盖范围）

| 功能 | 后端 | SDK | Proto | 前端 |
|------|------|-----|-------|------|
| 消息全文检索 | PG `pg_trgm` + GIN 索引 | 搜索 API | 新增 proto | 搜索 UI |
| 会话搜索 | 按名称/成员搜索 | 搜索 API | ✅ 已定义 | 搜索 UI |
| 全局搜索 (联系人+群+消息+文件) | 统一搜索网关 | 搜索 API | 新增 proto | 全局搜索入口 |
| 搜索过滤 (类型/时间/发送人) | 过滤参数支持 | 过滤参数 | 更新 proto | 过滤面板 |
| 搜索结果高亮 | 高亮片段返回 | 高亮展示 | 更新 proto | 高亮渲染 |

**产出**:
- 搜索引擎部署与数据同步
- 全局搜索页面
- 搜索过滤与高亮

## 优先级建议

```
MVP+ (1-2月) ─┬─ M1: 消息类型扩展与媒体
              ├─ M2: 群管理功能深化
              └─ M3: 消息互动与体验增强

标准版 (3-4月) ─┬─ M4: 搜索与发现
                ├─ M5: 多设备与离线体验
                └─ M6: 高级消息功能

企业版 (5-6月) ─┬─ M7: 管理与企业功能
                ├─ M8: 性能优化
                └─ M9: Web 端 IM (M1~M4 稳定后启动)
```

**建议立即启动 M1 + M2 并行开发**，它们是体验完善的基础；M3 (互动功能) 用户感知最强，建议紧随其后。

## 性能风险追踪

跨 Milestone 的性能风险汇总，标记严重度和引入阶段。

| # | 风险 | 引入阶段 | 触发条件 | 严重度 | 缓解方案 |
|---|------|---------|---------|--------|---------|
| 1 | **群消息推送顺序遍历** — `push_messages` 逐个 user 串行推 | 已存在 | 50+人群发消息 | 🔴 | 改为并发推 (`tokio::spawn` batch) 或 gateway 层做 fanout |
| 2 | **fill_entity 递归查询链** — feed→member→message→user N+1 | 已存在 | Feed 列表拉取 + 消息填充 | 🟡 | 批量预加载，减少重复 cache load |
| 3 | **feed_update_read_pos 写放大** — 当前为空函数，补上后 message_read 每次写 DB | 已存在 → M1 修复 | 大量消息已读操作 | 🟡 | 合并写、减频 |
