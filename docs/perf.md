# 性能问题记录

| # | 问题 | 方案 | 状态 |
|---|------|------|------|
| 1 | **`CACHE_CALENDAR` 读写锁竞争** — `write().await` 阻塞所有读 | 用 RwLock 写时 copy-on-write 或改用 moka 的细粒度失效 | ❌ 待观察 |
| 2 | **空扫描周期浪费** — 凌晨无日程时仍每 30s 执行 SQL | 已由 `schedule_reminders` 专表 + 部分索引消除，空窗口只需 B-tree seek | ❌ 不需要 |
| 3 | **cycled 展开无结束日期时的最大实例限制** — 400 限制在极端高频场景（每秒 1 次）仍可能产生大量实例 | 按需展开天然限制窗口（初始 120 天，增量仅查询范围），最小步长 1 天；400 安全网不会被触及 | ❌ 不需要 |
| 4 | **离线同步方案** — 用 pipeline 承载所有增量变更，重连只 drain pipeline，不做全量拉取 | **已设计：** §6 of Part 1；全量拉取仅限全新安装和 pipeline 数据丢失 | ✅ 已设计 |
| 5 | **pipeline 表无数据过期机制** — `pipelines` 表只增不删，长期运行后无限膨胀，影响离线用户重连时的拉取性能 | 定期清理（删除 `created_at < now - 30d` 或用户已读的旧记录）；或在 pipeline 表加 TTL 过期策略 | ❌ 待设计 |
